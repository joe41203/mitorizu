# ADR-001: PostgreSQL を採用する

- 状態: 承認済
- 日付: 2026-08-14
- 関連: REQ-005 / NFR-005 / ADR-005

## 背景

蔵書のメタデータを柔軟に持つ要件 (REQ-005) があり、
リレーショナルデータベースを選定する必要がある。

## 検討した選択肢

### 選択肢A: PostgreSQL (採用)

- 利点: JSON 型のサポート。全文検索が組み込み。拡張が豊富
- 欠点: 運用の知識が必要

### 選択肢B: MySQL

- 利点: 情報が多い。チームに運用経験がある
- 欠点: JSON の扱いが PostgreSQL より弱い

### 選択肢C: SQLite

- 利点: 運用が不要。開発が容易
- 欠点: 同時書き込みに弱い

## 決定

PostgreSQL を採用する。

### 理由

- JSON 型が必要 (REQ-005)
- 将来の全文検索を見据える

### MySQL を選ばなかった理由

運用経験はあるが、今回は JSON の利用が確定しているため機能を優先した。

### SQLite を選ばなかった理由

同時10接続 (NFR-005) を満たせない可能性がある。

## 結果

### この決定により決まること

- マイグレーションは PostgreSQL アダプタを使う
- インフラは RDS for PostgreSQL を選択する (ADR-005)

### この決定により制約されること

- 開発環境でも PostgreSQL が必要 (Docker で立てる)
- MySQL 固有の機能は使えない

### 見直す条件

- 全文検索の性能が不足した場合、外部の検索エンジン併用を検討する
- ただし DB の移行は行わない (コストが見合わない)
