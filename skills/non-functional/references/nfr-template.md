## 1. 想定規模

**全ての非機能要件はここから決まる。**

| 項目 | 現在 | 1年後 | マーカー |
| --- | --- | --- | --- |
| 利用者数 | 50人 | 100人 | [確実] |
| 同時アクセス | 10人 | 20人 | [推測] |
| 主要データ (蔵書) | 300件 | 500件 | [確実] |
| 主要データ (貸出記録) | 0件 | 3,000件 | [推測] |
| 利用時間帯 | 平日9-18時 | 同じ | [確実] |

**桁が違えば設計が変わる。** 1万件と100万件では必要なインデックスが違う。

## 2. 性能

| ID | 要件 | 測定条件 | マーカー |
| --- | --- | --- | --- |
| NFR-001 | 一覧 API を95パーセンタイル1,000ms 以内で応答する | 蔵書1,000件・同時10接続 | [推測] |
| NFR-002 | 画面の初期表示を3秒以内に完了する | 同上 | [推測] |
| NFR-003 | 貸出処理を2秒以内に完了する | 同上 | [推測] |

**測定条件を必ず書く。** 「何件のデータで」「何接続で」が無いと検証できない。

## 3. 可用性

| ID | 要件 | 値 | 根拠 | マーカー |
| --- | --- | --- | --- | --- |
| NFR-010 | 稼働率 | 99% (月7時間の停止を許容) | 社内ツールのため | [確実] |
| NFR-011 | 復旧時間 (RTO) | 4時間以内 | 翌営業日までに復旧すればよい | [推測] |
| NFR-012 | データ損失 (RPO) | 24時間 (日次バックアップ) | 手入力で復元可能な量 | [推測] |
| NFR-013 | 計画メンテナンス | 許容する (事前通知) | - | [確実] |

**MVP では単一構成でよいことが多い。** Multi-AZ はコストが倍になる。

ただし**バックアップだけは最初から取る。** データを失うと復旧できない。

## 4. セキュリティ

### 認証・認可

| ID | 要件 | マーカー |
| --- | --- | --- |
| NFR-020 | 全ての通信を TLS 1.2 以上で暗号化する | [確実] |
| NFR-021 | パスワードは bcrypt でハッシュ化して保存する | [確実] |
| NFR-022 | ロールは「一般」「管理者」の2種類とする | [確実] |

### 個人情報

**MVP でも必ず決める。** 法的要件に関わる。

| 情報 | 保持するか | 保持期間 | 暗号化 | 根拠 |
| --- | --- | --- | --- | --- |
| 氏名 | する | 退会後1年 | しない | 貸出記録の表示に必要 |
| メールアドレス | する | 退会後1年 | しない | 認証に必要 |
| 電話番号 | **しない** | - | - | 業務上不要 |
| 住所 | **しない** | - | - | 業務上不要 |

**保持しないという判断が最も安全。** 必要になってから追加する。

### 監査ログ

| ID | 要件 | マーカー |
| --- | --- | --- |
| NFR-030 | 貸出・返却の操作者と日時を記録する | [確実] |

**後付けは過去分が残らない。** 要否だけは最初に決める。

## 5. 運用

| 項目 | 決定 | マーカー |
| --- | --- | --- |
| アプリログ | 30日保持 | [推測] |
| 監視 | 死活監視のみ (5分間隔) | [確実] |
| 通知先 | Slack の #alerts チャンネル | [要確認] |
| バックアップ | 日次・7世代 | [確実] |
| デプロイ | 週次。ダウンタイムを許容する | [確実] |
| 障害対応 | 平日日中のみ | [推測] |

**MVP では監視を最小にしてよい。** ただし死活監視だけは入れる。
落ちていることに気づかないのが最悪。

## 6. 拡張性

**今の10倍までを想定する。** それ以上は「その時に考える」と明記する。

| ID | 想定 | 対応方針 | マーカー |
| --- | --- | --- | --- |
| NFR-040 | 蔵書が10倍 (3,000件) | ページネーションで対応する | [推測] |
| NFR-041 | 利用者が10倍 (500人) | サーバーの垂直スケールで対応する | [推測] |
| NFR-042 | それ以上の規模 | 現時点では設計しない | [確実] |

**「無限にスケールする設計」を目指さない。** MVP では過剰。

## 7. MVP では決めないこと

| 項目 | 理由 | いつ決めるか |
| --- | --- | --- |
| 多言語対応 | 国内利用のみ | 海外展開を検討する時 |
| SLA | 社内ツールのため契約なし | 外部提供する時 |
| 災害対策 (DR) | 停止しても業務が止まらない | 業務クリティカルになった時 |

## 8. 検証方法

**どう確認するかを書かない要件は、満たされたか分からない。**

| 要件ID | 検証方法 | 実施時期 |
| --- | --- | --- |
| NFR-001 | 蔵書1,000件を投入し、ab で10並列100リクエストを実行 | 実装後 |
| NFR-012 | バックアップから復元し、データが揃うことを確認 | リリース前 |
| NFR-020 | SSL Labs でグレードA以上を確認 | リリース前 |
| NFR-040 | (検証しない。設計上の想定のみ) | - |

**検証しないものは「検証しない」と書く。** 曖昧にしない。
